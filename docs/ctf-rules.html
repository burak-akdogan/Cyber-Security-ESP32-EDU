🚩 Classroom CTF — Student Rules

Read this before the round starts. Full technical design: see CLASSROOM-CTF-EVENT-en.md in the repo.

Your class is running a live Capture-the-Flag round against a Raspberry Pi projected on the classroom screen. Find hidden "flags" hiding behind real, common web-server vulnerabilities — then, if you can, patch the vulnerability you found so no one else can score from it.

Before you start

⚠️ Only ever target the instructor's Raspberry Pi on the event Wi-Fi. Never point any tool at another student's device, the school network, or anything you don't have explicit permission to test. This follows the same Code of Conduct as every other lab in this project.

How to play

  1. Join the event Wi-Fi network (ask your instructor for the name/password and the Pi's IP address).
  2. Flash an ESP32 with the CTF Recon Scanner or CTF Flag Prober tool from the flashing site — no coding needed, just connect and send the Wi-Fi info + target IP.
  3. Watch the Console for anything that starts with [FOUND] — that's a captured flag.
  4. Type your team name and the flag into the scoreboard page on the projected screen.
  5. Optional: patch the vulnerability you found (one click on the scoreboard) to lock it and earn a bigger bonus.

What you're looking for

Seven vulnerability categories are planted on the Pi. No spoilers here — just the categories, so you know what skill each one is testing:

  • #1 — Default credentials. Some accounts still use the password they shipped with.
  • #2 — Hidden pages aren't secret. Not being linked anywhere isn't the same as being protected.
  • #3 — Broken access control (IDOR). What happens if you just... change an ID in the URL?
  • #4 — Leftover files. Developers sometimes forget to remove things from a live server.
  • #5 — Oversharing errors. A crash message can say more than it should.
  • #6 — Missing authentication. Not every sensitive action checks who's asking.
  • #7 — Untrusted input (hardest). What a service does with input it never expected.
